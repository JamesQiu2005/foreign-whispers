# Apple Silicon Adaptation Summary

How this fork was ported from the course's CUDA-Docker setup to bare-metal
Apple Silicon (M3 Max, macOS), without GPU passthrough or Docker.

## TL;DR

```bash
# one-time
brew install pnpm rubberband imagemagick   # ffmpeg + deno + node already assumed
uv sync                                     # installs torch from PyPI (MPS)
cd frontend && pnpm install && cd ..

# every run
FW_WHISPER_MODEL=base uv run uvicorn api.src.main:app --host 0.0.0.0 --port 8080 &
cd frontend && API_URL=http://localhost:8080 PORT=8501 HOSTNAME=0.0.0.0 pnpm dev
# → http://localhost:8501
```

## What changed in the repo

| File | Change | Why |
|---|---|---|
| `pyproject.toml` | Removed `[tool.uv.sources]` torch/torchaudio/torchvision pins, the `pytorch-cu128` index, and the cu128 `find-links`. | The CUDA-only wheel index has no macOS wheels — `uv sync` failed. PyPI's torch ships with MPS. |
| `uv.lock` | Regenerated by `uv sync`. | Resolves `torch==2.11.0` from PyPI instead of the cu128 index. |
| `.gitignore` | Added `.DS_Store`. | macOS Finder droppings. |
| `CLAUDE.md` | Replaced Docker-only run instructions with bare-metal `uv run` + `pnpm dev`. | The original asserts "Always use Docker Compose" — false on Mac. |
| `CLAUDE_reference.md` | New file: verbatim copy of the original Docker-centric `CLAUDE.md`. | Preserved for reference / future hosts with NVIDIA GPUs. |

No Python source code (`api/src/**`, `foreign_whispers/**`) was modified —
the existing local fallbacks were already sufficient (see next section).

## Why no service code changes were needed

The codebase already has local-mode paths the Docker setup doesn't exercise:

- **Whisper STT** — `api/src/main.py:48-55` `get_whisper_model()` calls
  `whisper.load_model(...)` directly (the OpenAI Whisper Python package).
  No `:8000` HTTP service required. `transcribe.py` defaults
  `use_youtube_captions=True`, so for any video with YouTube captions
  Whisper isn't even invoked.
- **Chatterbox TTS** — `api/src/services/tts_engine.py:128-158`
  `_make_tts_engine()` probes `CHATTERBOX_API_URL` at startup with a real
  test synthesis call. On any failure (e.g., nothing on `localhost:8020`)
  it falls back to local Coqui `tts_models/es/mai/tacotron2-DDC` on CPU.
  This fallback path is what runs on Mac.
- **Translation** — `argostranslate` is CPU-only by design.
- **Stitch** — `ffmpeg` remux, no GPU.
- **Diarization** — only required by the Phase 2 diarization notebook;
  `pyannote.audio` runs on CPU/MPS without modification.

## Limitations of the Apple Silicon setup

1. **TTS quality is the floor, not the ceiling.** Coqui Tacotron2 CPU is
   meaningfully worse than Chatterbox GPU (no voice cloning, more brittle
   on punctuation / short fragments). The Phase 2 improvements are still
   real but measured against a uglier baseline.
2. **Spanish-too-short, not Spanish-too-long.** The course's framing
   assumes Spanish translations overflow the source window. With Coqui's
   pacing on this hardware, the dominant artifact is the opposite —
   segments come out shorter than target and `pyrubberband` stretches
   them >1.33× to fill the gap, producing wobbly/drunk audio. This
   shifts which Phase 2 tasks pay off most (alignment DP > translation
   reranking).
3. **TTS may emit empty output for some segments.** When Coqui fails on a
   segment, `_synthesize_raw` returns `None` and the post-processor pads
   with silence. This shows up in `.align.json` as
   `raw_duration_s: 0.0`. A small retry/sanitize fix in
   `tts_engine._synthesize_raw` is a useful Phase 2 side-quest.
4. **No GPU = slow first-run for Whisper-base.** YouTube captions
   short-circuit this most of the time.

## Environment variables

`api/src/core/config.py` uses `pydantic-settings` with `env_prefix="FW_"`
but **does not** declare `env_file=".env"` — so `.env` is **not**
auto-loaded. Two ways to use it:

```bash
# A. shell-export at run time (current approach — no code change)
set -a && source .env && set +a
uv run uvicorn api.src.main:app --host 0.0.0.0 --port 8080

# B. one-line patch to config.py:
#   model_config = {"env_prefix": "FW_", "env_file": ".env"}
```

Tokens that matter:
- `FW_HF_TOKEN` — required for Phase 2 diarization notebook only.
  Token must have access to `pyannote/speaker-diarization-3.1` (accept
  the gated license at https://huggingface.co/pyannote/speaker-diarization-3.1).
- `FW_LOGFIRE_WRITE_TOKEN` — optional observability. Skip.
- `CHATTERBOX_API_URL` — leave unset (or unreachable) to trigger the
  Coqui fallback. Set to a hosted Chatterbox if/when one is available.

## YouTube downloads / cookies

The Docker compose mounts `./cookies.txt` into the API container. On Mac
bare-metal, yt-dlp will try anonymous first. If you hit
`Sign in to confirm you're not a bot`:

- Quick: install the *Get cookies.txt LOCALLY* browser extension, export
  YouTube cookies, save to repo root as `cookies.txt`.
- Cleaner: pass `--cookies-from-browser chrome` directly to yt-dlp in
  `api/src/services/download_engine.py`.
- Last resort: download the MP4 manually and drop it into
  `pipeline_data/api/videos/<video-title>.mp4`. The rest of the pipeline
  picks up from there.
